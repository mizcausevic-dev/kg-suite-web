Prove what your AI actually does.
Before a buyer, regulator, or agent has to guess.

Kinetic Gain is a set of open JSON specs that let an AI vendor declare what a system is, what it refuses, what evidence backs its claims, and what happens when it fails, so procurement teams, compliance reviewers, and other AI agents can verify it automatically instead of taking your word for it.

02 - Overview

The core layer

Each spec carries a top-level <name>_version field. The MCP server exposes fetch / validate / inspect / cross-spec-join tools for all twelve specs. The eleven regulated-vertical 6-packs, HealthTech, EdTech, PropTech, InsurTech, HR Tech, FinTech, GovTech, LegalTech, EnergyTech, DefenseTech, RetailTech, fan the same six canonical artifact shapes across 66 sibling spec repos; see /verticals/ for the full extension layer.

Cross-cutting - when things break

AI Incident Card

Post-incident disclosure, the "CVE for AI agents". References every other affected document. Vendor-published.

AI Procurement Decision Card

Buyer-side artifact, records a buyer's procurement review of vendor declarations. Closes the loop. Buyer-published.

Distribution — pin from your own CI

The Suite ships through three consumer-pinnable channels. Code can sit on GitHub all day; if consumers can't pin from their own CI / package manager, it doesn't move.

🛍️ GitHub Marketplace. 21 protocol PR-gate + governance Actions, each with v0.1.0 exact-pin + floating v0.1 major tags: 

uses: mizcausevic-dev/agent-card-diff-action@v0.1      # floating major
uses: mizcausevic-dev/agent-card-diff-action@v0.1.0    # exact pin

📦 npm registry. kinetic-gain-embedded@0.1.1 (Apache-2.0, dual ESM/CJS, zero runtime deps, Node 20+, npm provenance-stamped) — drop-in audit-stream + Decision Card vault contract SDK. Plus mcp-kinetic-gain@0.9.1 (75 tools, on the official MCP Registry).
