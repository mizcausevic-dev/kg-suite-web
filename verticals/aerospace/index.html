Make the assurance story inspectable.

A vendor-side aviation ML disclosure, an artifact-bound AI-assisted maintenance review, and dataset provenance checks. Each fits the existing Protocol Suite. None is an airworthiness approval, a maintenance release, or a regulatory filing.

One Suite extension, four linked assets

What travels with the system and the work

Two cards define what the vendor discloses and what a human reviewed. A dataset tool checks concrete engineering properties. A crosswalk identifies the public sources behind the questions.

01

Vendor disclosure · draft spec

Aviation ML Assurance Card

Identifies the system, intended use, proposed EASA AI level, target design-assurance level, operational conditions, learning process, dataset references, and human role. Each declared operating condition can point to its own evidence.

Read the draft spec

The card records a vendor assertion. It does not assign a DAL or prove that evidence is sufficient.

02

Per-artifact review · draft spec

MRO AI Sign-off Card

Binds an AI-assisted maintenance finding to the model version, inspected artifact hash, evidence references, human decision, and review signature. It can record an override and the reviewer’s authority reference.

Read the draft spec

A signed review is not a certificate of release to service or proof of staff privileges.

03

Engineering check · public draft

Dataset provenance

The Rust tool hashes dataset files and a manifest, checks train, validation, and test split overlap, and reports coverage gaps against declared operating conditions. It can sign its reports with the existing hash-attestation library.

Inspect the source and test fixtures

A hash proves byte identity, not collection rights, labeling quality, or real-world coverage.
